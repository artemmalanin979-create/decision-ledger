# Как читать выгрузку пилота

Пилот охватывает 14 дней входящих голосовых вызовов. До старта участников распределили по профилям пользования связью и случайно назначили один из трёх режимов внутри каждого профиля. Одна строка — итог для пары `cohort` и `group`. Профили взаимно исключают друг друга. В выгрузке только синтетические агрегаты.

| Поле | Значение |
| --- | --- |
| `cohort` | Профиль абонентов, определённый до пилота. `everyday` — обычное использование, `service_callbacks` — частые обратные звонки от служб, `priority_callbacks` — абоненты, которые заранее отметили важность срочных обратных звонков с незнакомых номеров. |
| `group` | `as_is` — текущая обработка вызова с обычным отображением номера, `warning` — метка подозрительного звонка с возможностью ответить, `hard_block` — отклонение вызовов с высоким риском до соединения. |
| `eligible` | Все входящие вызовы участников, подпавшие под заранее заданные правила учёта пилота. Включает спам, легитимные звонки и вызовы без подтверждённой категории. Это общий знаменатель для обеих метрик. |
| `avoided_spam` | Вызовы, подтверждённые как спам в ходе разбора пилота, которые абонент не принял. В `as_is` абоненты также могут самостоятельно отклонять или игнорировать звонки. |
| `missed_important` | Подтверждённые легитимные звонки, которые абонент ожидал и не смог принять вовремя. Сюда попадают, например, обратный звонок из клиники или звонок о срочном выезде специалиста. Учёт одинаков для всех режимов и включает естественные пропуски в `as_is`. |

Доли по режиму считаются из суммы соответствующих счётчиков, делённой на сумму `eligible`. Доли по профилю считаются внутри строки. Эффект по спаму — разница долей `avoided_spam` с `as_is` в процентных пунктах.

**Порог безопасности для расширения.** Доля `missed_important` не выше 0,30% в целом по режиму и в каждом профиле. Превышение в любом профиле исключает расширение режима. Ровно 0,30% допустимо. Это порог для наблюдаемой доли от всех вызовов пилота, а объём всех важных звонков отдельно не измерялся.

**Окно сверки.** Для подтверждения пропуска используют обращения в поддержку и контрольный опрос участников. После последнего дня пилота на сбор запоздавших сообщений отведено ещё семь дней. `pilot.csv` — срез до закрытия этого окна. Обращения могут недоучитывать пропуски, даже после сверки. Выгрузка агрегирована по вызовам, поэтому из неё нельзя оценить разброс по отдельным абонентам.
