# Сценарий демонстрации для команды

Это вымышленный кейс о запуске продукта для небольших магазинов. На старте передаётся содержимое `initial/`. Ответ руководителя используется после уточнений. Памятка остаётся у ведущего, а `recount.csv` появляется после первого решения.

## Первый сеанс

> Помоги подготовить решение для комитета о резервном интернете для небольших магазинов. Разберись с входящими материалами. Если варианты зависят от неизвестных требований, задай только вопросы, которые меняют рекомендацию.

После вопросов передайте текст `manager.md`.

> Сравни варианты, раздели рыночные факты, результаты испытаний и предположения по экономике. Предложи продукт, фразу для владельца магазина и проверку на следующий этап. Сохрани критерии, расчёт, решение и условия пересмотра, чтобы к ним можно было вернуться в новом сеансе.

Ожидаемый выбор — подготовить ограниченный платный пилот настроенного резерва для обоих типов касс с допуском только после сверки. Владелец получает проверку конкретной кассы при отключении проводного интернета. В демонстрации явно назовите условия проверки, включая питание, доступный LTE и работоспособность платёжного сервиса.

## Новый сеанс и новая выгрузка

Откройте отдельный сеанс в той же рабочей папке.

> Найди сохранённое решение по резерву связи для магазинов. Кратко восстанови выбранный вариант, что его обосновывает и какое событие должно привести к пересмотру.

Затем передайте `later/recount.csv`.

> Пришла сверка журналов касс, тестовых оплат и чеков. `recount.csv` заменяет `pilot.csv` и относится к тем же отключениям. Пересчитай общий результат и допуск по каждому типу кассы. Обнови решение, клиентское обещание и следующий тест. Сохрани старую версию и укажи, какой новый факт изменил выбор.

После сверки разрешён платный пилот только для `direct_pos` с проверкой каждой кассы на месте. Для `legacy_gateway` следующий шаг — локализовать расхождения по журналам и повторить тест до допуска. В качестве возможной причины можно проверить запоздалую синхронизацию статуса через шлюз. Сводная выгрузка причины не устанавливает.

## Эталонные расчёты

Все доли рассчитаны от числа прогонов. На каждый режим приходится 260 прогонов, из них 240 в `direct_pos` и 20 в `legacy_gateway`. Пороги проверяются по исходным числам, проценты округлены для показа.

| Режим | Восстановлена связь, оба среза | Завершены покупки, до и после | Ложные успехи, до и после |
| --- | ---: | ---: | ---: |
| Текущая схема | 161 / 260 = 61,92% | 146 / 260 = 56,15% | 0 / 260 = 0% |
| Самостоятельное подключение | 227 / 260 = 87,31% | 217 / 260 = 83,46% | 1 / 260 = 0,38% |
| Настроенный резерв | 258 / 260 = 99,23% | 252 / 260 = 96,92% → 245 / 260 = 94,23% | 0 / 260 = 0% → 7 / 260 = 2,69% |

| Тип кассы с настроенным резервом | Восстановлена связь, оба среза | Завершены покупки, до и после | Ложные успехи, до и после |
| --- | ---: | ---: | ---: |
| `direct_pos` | 238 / 240 = 99,17% | 232 / 240 = 96,67% → 231 / 240 = 96,25% | 0 / 240 = 0% → 1 / 240 = 0,42% |
| `legacy_gateway` | 20 / 20 = 100% | 20 / 20 = 100% → 14 / 20 = 70% | 0 / 20 = 0% → 6 / 20 = 30% |

Для всех типов вместе настроенный резерв после сверки всё ещё проходит оба порога. `legacy_gateway` проваливает оба, хотя связь восстановилась во всех 20 прогонах. Прирост по завершённым покупкам в допущенном `direct_pos` — 231 / 240 минус 137 / 240, то есть +39,17 п. п. к текущей схеме. Самостоятельный комплект даёт 83,46% завершённых покупок в целом и 84,17% в `direct_pos`. Это отдельное предложение связи, и таблица не подтверждает спрос на него.

Расчётный вклад до накладных расходов — 740 ₽ / 1 290 ₽ = 57,36% для самостоятельного комплекта и 1 290 ₽ / 2 490 ₽ = 51,81% для настроенного резерва. При цене 2 490 ₽ и пороге 45% прямые затраты на настроенный резерв могут быть не выше 1 369,50 ₽ в месяц. Запас к гипотезе затрат — 169,50 ₽. Для платного пилота проверяют принятие цены и фактические затраты на точку. Стендовая частота успеха не является оценкой доли спасённых покупок в магазинах.

Пример фразы для владельца магазина. «Настроим автоматический резерв на LTE и проверим на вашей кассе, что при отключении проводного интернета проходит контрольная оплата и формируется чек. Подключаем после проверки связи в помещении и совместимости кассы».
