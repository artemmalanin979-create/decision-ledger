# Примеры резервной связи и проверки оплаты

Три открытых первичных источника проверены 7 ноября 2026 года. Два коммерческих примера относятся к США. Документация описывает механизмы и ограничения конкретных продуктов. Результаты для местных магазинов и цены учебного пилота из неё не следуют.

- **M1 · Verizon Business.** У оператора есть беспроводной резерв на случай сбоя проводного интернета. Доступность проверяют по адресу, нужен совместимый роутер. Для работы при отключении электричества понадобится резервное питание. [Verizon Backup and Flexible Use Internet](https://www.verizon.com/business/products/internet/backup-failover/)
- **M2 · Digi.** В примере настройки роутер проверяет доступность контрольного адреса по основному каналу. После нескольких пропущенных ответов меняет маршрут на мобильный, а затем продолжает проверять приоритетный канал. Такая проба подтверждает доступность заданного адреса. [Digi, пример перехода с Ethernet на мобильный канал](https://docs.digi.com/resources/documentation/digidocs/90002431/os/wan-failover-example-r.htm)
- **M3 · Square.** Офлайн-платёж может отображаться в ожидании. После восстановления связи и отправки записей он может быть подтверждён или отклонён. Для оценки результата важно сверять окончательный статус. Это пример из другого платёжного продукта, а не диагноз для касс в испытаниях. [Square Support, просмотр офлайн-платежей](https://squareup.com/help/us/en/article/8551-view-offline-payments)
