# Как читать выгрузку контрольных отключений

В стендовых испытаниях сравнивали три режима на одних и тех же тестовых конфигурациях касс. Для каждого сценария воспроизводили одинаковую длительность сбоя проводного интернета в каждом режиме, чередовали порядок режимов и сбрасывали состояние между прогонами. В части сценариев основной канал возвращался в пределах минуты. Питание сохранялось, доступность LTE заранее проверили. Использовали эмуляторы оплаты и чеков. Данные синтетические.

В каждой строке один тип кассы и один режим. Повторные прогоны на одной конфигурации не являются независимыми магазинами. В `direct_pos` 24 конфигурации по 10 прогонов на режим. В `legacy_gateway` четыре конфигурации по пять прогонов на режим. Итоги взвешены по прогонам и зависят от состава испытаний.

| Поле | Что измеряли |
| --- | --- |
| `cohort` | Заранее заданный тип кассы. `direct_pos` — кассовое ПО обращается к платёжному сервису напрямую. `legacy_gateway` — касса получает статус оплаты через локальный шлюз старого поколения. |
| `group` | `as_is` — существующая проводная схема. `self_service` — SIM и LTE-роутер, персонал переключает кассу по инструкции. `managed_failover` — заранее настроенный автоматический переход на LTE с приёмочным тестом кассы при подключении. |
| `drills` | Число запланированных прогонов с отключением проводного канала. В каждом прогоне одна контрольная покупка. Это знаменатель всех трёх долей. |
| `network_recovered` | Прогоны, в которых за 60 секунд после отключения кассовая сеть снова достигла внешнего контрольного адреса. Проба проверяет сеть. |
| `checkout_completed` | Прогоны, в которых за 120 секунд после отключения контрольная покупка получила одно подтверждение оплаты и один соответствующий тестовый чек. Предварительный срез использует локальные статусы касс до сверки. |
| `false_success` | Прогоны, в которых касса показала успех в отведённое время, а сверка выявила отсутствующее, запоздалое или дублированное подтверждение оплаты либо несоответствие тестового чека. Такие прогоны исключаются из `checkout_completed`. Открытый отказ на кассе сам по себе в эту колонку не попадает. |

Для доли по режиму разделите сумму счётчиков на сумму `drills`. Для доли по типу кассы используйте соответствующую строку. Сетевой успех и исход покупки могут учитываться в одном прогоне. В каждой строке `checkout_completed` и `false_success` взаимоисключающие.

**Порог для платного пилота с проверкой кассы.** Не менее 90% завершённых контрольных покупок и не более 3% ложных успехов. Оба порога действуют в целом и по каждому типу кассы, который планируется подключать. Пограничные значения допустимы. Сетевая проба сама по себе не даёт допуска.

`pilot.csv` — предварительная выгрузка. Для финальной сверки нужно сопоставить время и статус в журналах кассы, эмулятора платёжного сервиса и журнала тестовых чеков в течение двух рабочих дней после испытаний. Нулевой `false_success` до сверки означает, что несоответствия пока не выявлены.
