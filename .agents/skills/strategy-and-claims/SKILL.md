# Навык: Синтез стратегии и аудит обещаний

1. Сформируй минимум три содержательно разных варианта с обязательными типами `keep` («оставить как есть»), `change` (один или несколько продуктовых ходов) и `close` («закрыть направление / снять инициативу»).
2. Для каждого варианта заполни механизм пользы, экономику, **сильнейшее возражение** и конкретные `depends_on` на узлы `findings`.
3. Согласуй три блока стратегии (`product`, `communication`, `experiment`):
   - **Продуктовая**: целевой сегмент и его задача, альтернативы, минимальный состав решения, **осознанные отказы** (кого и что не берём сейчас), связь с юнит-экономикой.
   - **Коммуникационная**: ситуация выбора, барьер доверия/понимания, проверяемое ключевое сообщение, **условия применимости обещания** и роль каналов.
   - **План проверки**: ожидаемый сдвиг, база сравнения, срок, защитные метрики по когортам и чёткое **стоп-правило**.
4. Перед показом руководителю прогони черновик через субагента `agents/skeptic-reviewer.md` и выполни:
   ```sh
   python3 -m ledger propose .cases/<имя> proposal.json --strict-claims
   python3 -m ledger dashboard .cases/<имя>
   ```
5. Покажи руководителю краткую развилку, SHA черновика и ссылку на `dashboard.html`. Никогда не вызывай `accept` без явного подтверждения человека в текущем диалоге.
