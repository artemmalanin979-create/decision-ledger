# Навык: Постановка задачи и маршрутизация

Используй на старте нового кейса или при неясном запросе руководителя продукта.

1. Инициализируй кейс (`python3 -m ledger init .cases/<имя> "<запрос>"`) или проверь существующий (`python3 -m ledger status .cases/<имя>`).
2. Вызови маршрутизатор `python3 -m ledger route .cases/<имя>` (или MCP-инструмент `ledger_route`), чтобы увидеть состав входных файлов, модальности и рекомендуемый дешёвый маршрут.
3. Прочитай разрешённый бриф и проверь в базе знаний (`python3 -m ledger kb search "<тема>"`), были ли связанные кейсы. Помни: записи `prior_conclusion` — это контекст прошлых решений, а не первичный факт.
4. Задай человеку **не более трёх вопросов**, каждый из которых меняет набор вариантов, целевую метрику, сегмент допуска, бюджет/срок или границы обещания клиенту. Всё обратимое сформулируй как явное рабочее допущение.
5. Сохрани контрольную точку (`python3 -m ledger checkpoint .cases/<имя> intake "<следующий шаг>"`).
