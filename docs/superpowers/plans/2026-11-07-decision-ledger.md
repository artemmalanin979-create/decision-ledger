# Decision Ledger Implementation Plan

> Для выполнения по шагам используйте superpowers:executing-plans.

**Цель** — воспроизводимый путь от нечёткого запроса до пересмотра принятого решения.

**Архитектура** — IDE выполняет исследование. Локальный Python CLI хранит состояние и даёт проверяемые расчёты.

**Спецификация** — [Decision Ledger](../specs/2026-11-07-decision-ledger-design.md).

## Ограничения и проверки

- Python 3.11+, только стандартная библиотека. Источники открытые или собственные. Русский язык в интерфейсе агента.
- Изменение файла по старому пути затрагивает зависимые выводы. Новые источники требуют триажа. Пустые знаменатели отображаются как неизвестные. Повтор команды не дублирует принятие. Прерванная запись сохраняет предыдущий реестр. Веб-сбой и недостающие сведения остаются в контрольной точке.

## Задачи

- [ ] Тест CLI на цепочку из двух выводов и обновление одного файла. Реализовать `init`, `source`, `propose`, `accept`, `status`, `checkpoint`, `view`, `done`. Проверить устаревший черновик и ранее принятый снимок.
- [ ] Тест расчёта взвешенных долей и отклонения испорченного CSV. Добавить `rates`, проверить метрики в разрезе сегментов.
- [ ] Написать инструкции IDE и методы для исследования, развилок, продукта, сообщений, эксперимента и пересмотра.
- [ ] Прогнать демонстрацию с отдельным подтверждением и новым чатом. Сравнить с разовым запросом той же модели и задокументировать условия сравнения.
- [ ] Собрать конкурсное описание и запись, прогнать тесты и проверить запуск из чистого клона.
