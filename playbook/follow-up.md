# После выбора

1. Прочитай `status`. При новых данных задай стабильный ID нового источника или повторно зарегистрируй тот же ID, если это уточнение прежнего источника. Версия сохраняется по SHA-256. Если новые данные приходят самостоятельным документом или пресс-релизом, передай `--updates <id_источника_или_вывода>` в `source` или `fetch`, чтобы граф `approved_impact` сразу вычислил транзитивно затронутые узлы без перезаписи старого снимка.
2. Прочитай `approved_impact`. Покажи цепочку источник → наблюдение → вывод → вариант/часть стратегии. Если есть `unreviewed`, сравни новые данные с прежним выводом и зафиксируй, что они подтверждают, опровергают или уточняют. В приложении есть ссылки на уровне утверждений. Смысловую связь для нового источника определяет модель.
3. При `changed` или `unavailable` сообщи об этом. Для точного сравнения используй `evidence <кейс> <старый sha>`. Повторно зарегистрируй правку после проверки происхождения. Если источник отозван, вызови `retire` с причиной, исключи его из нового черновика и поясни влияние. Сохрани старую версию для аудита.
4. Сравни исходные пороги с новыми числами, проверь сегменты и ложные прокси. Укажи, какие варианты и обещания остаются обоснованы. Подготовь новую рекомендацию и отдельно вынеси существенный выбор человеку. Пока он открыт, покажи безопасное промежуточное действие и его ответственного.
5. Просроченное обязательство покажи с ответственным, датой и следующим шагом. Применяй `done` только по предоставленному подтверждению. При пересмотре перенеси действующие обязательства в новый черновик и перечисли снятые с объяснением.
